# SkiMo with image observations: learning exercises

Paper: [Skill-based Model-based Reinforcement Learning](https://arxiv.org/pdf/2207.07560),
especially Section 3.3, equations 2–5.

This is an educational adaptation of offline joint pretraining, not a complete
SkiMo reproduction. You implement the models, Gaussian math, losses, and optimizer
step. The data generator, preview utility, and training loop are supplied.

## What changes from image VQ-VAE?

VQ-VAE reconstructs a single image using discrete dictionary entries. SkiMo learns
a continuous skill from a sequence of observations AND actions. A skill policy
reconstructs the actions, and a skill dynamics model predicts the result of executing
the entire skill. Images are observations here; they alone do not provide the
supervised actions required by this exercise.

There are two distinct latent spaces:

| Symbol | Meaning | Default shape |
| --- | --- | --- |
| s_t | observed image | [B,1,28,28] |
| h_t | continuous image state, E(s_t) | [B,32] |
| a_t | normalized horizontal/vertical movement command | [B,2] |
| z | continuous skill lasting H=10 actions | [B,4] |

There is no codebook or nearest-neighbor quantization. Unlike our VQ-VAE objective,
this skill VAE has a nonconstant KL penalty against a standard Gaussian in the
pre-tanh space.

## Dataset and alignment

A Gaussian dot moves across 28x28 grayscale images. Each example has two motion
blocks, each with a roughly constant command, for a total of 20 actions and 21
images. Actions move the dot by 0.025 times the normalized command, with clipping
at the borders. Effective commands account for clipping. Positions are used only
inside the generator; the model receives images and actions.

```text
block 0: images s_0 ... s_9  + actions a_0 ... a_9 -> skill z_0
block 1: images s_10 ... s_19 + actions a_10 ... a_19 -> skill z_1

h_0 --D(h_0,z_0)--> predicted h_10 --D(predicted h_10,z_1)--> predicted h_20
                       target E_target(s_10)                 target E_target(s_20)
```

The last frame is an outcome, not an additional action input. Infer each posterior
skill using its observed block, but roll dynamics recursively through predicted
states. Resetting to observed states at each block would remove multi-step training.

Run from the workspace root using the same environment as project 01:

```bash
python 02_skimo/checks.py data
python 02_skimo/train.py --preview-data
```

`outputs/trajectory.png` contains 21 consecutive frames in raster order. A motion
block is not aligned to an image-grid row: each block has 10 actions and 11 frames
including its endpoint. The two blocks share their boundary frame.

## 1. Image representation

Implement ImageEncoder and ImageDecoder in model.py. The encoder should output a
single continuous vector per image, not a quantized feature grid. You can adapt
your earlier convolutional layers, flatten the final grid, and add a linear layer.
The decoder needs a linear projection back to a spatial feature grid before its
upsampling layers. Add hidden nonlinearities and a final sigmoid.

First verify manually that decoding an encoded batch returns the original image
shape. A useful preliminary experiment is training only this image autoencoder.
This isolates visual representation problems from skill-learning problems.

## 2. Continuous skill VAE

Implement sample_skill, SkillEncoder, SkillPolicy, and diagonal_kl.

The skill encoder sees H observed states and their H actions. For this small
fixed-horizon exercise an MLP over the flattened sequence is sufficient. It outputs
mu and logvar of a diagonal Gaussian. Reparameterize a base sample u, then apply
tanh to obtain z. The same sampled z conditions every action in that block.

The policy takes the CURRENT observed state and z, returning one action. For
batched reconstruction, repeat z across the block and flatten batch/time before
calling the policy. This is teacher forcing: at training time each action uses
the actual observed state, not a state generated by a rollout.

For the KL helper, sum over latent coordinates and leave other dimensions intact.
The loss function will average over batch and block. Check the identical-Gaussian
case (zero KL) and the unit-variance case with shifted means.

```bash
python 02_skimo/checks.py gaussian
```

## 3. Skill dynamics and target encoder

Implement SkillDynamics as an MLP on concatenated h and z. One call predicts the
state H actions later, not the immediate next frame. Predict a continuous state
vector; use the image decoder separately to visualize it.

A frozen copy of the image encoder supplies targets. Implement update_target with
an exponential moving average after each optimizer step. tau=0.01 means 1% online
parameters and 99% previous target parameters. A frozen target has no optimizer
gradients but still changes through this explicit update.

```bash
python 02_skimo/checks.py target
```

## 4. State-conditioned skill prior

The posterior sees a whole observed trajectory; the learned prior sees only its
starting state. Implement SkillPrior to predict Gaussian parameters from h.
Match it to the posterior distribution with KL(q || p), detaching BOTH posterior
parameters for this term. This teaches the prior plausible skills without letting
it pull the posterior toward an easy answer. In this adaptation detach the prior's
input h as well, so this term trains only prior parameters.

Distinguish the two priors: the STANDARD NORMAL regularizes the skill VAE; the
LEARNED state-conditioned prior predicts skills present in offline data.

## 5. Joint pretraining

Implement SkiMo.forward following its output dictionary contract, then
pretrain_loss and train_step. A simple loop over the two blocks is fine. Keep
predicted state tensors attached across the recursive rollout for backpropagation
through time. Compute target states under no_grad.

| Component | Desired behavior |
| --- | --- |
| action MSE | Skill policy reproduces observed commands |
| Gaussian KL | Posterior stays near the fixed standard normal |
| image MSE | State vectors retain visual information |
| dynamics MSE | Skills predict future latent states |
| prior KL | Starting state predicts posterior skill distribution |

Return unweighted loss components for logging and apply weights only in the total.
Default weights are teaching choices, not paper hyperparameters. Background pixels
dominate dot images: a low image MSE can coexist with missing dots, so inspect the
previews as well as the numbers. Image reconstruction prevents an easy constant
state solution, but does not guarantee good representations by itself.

```bash
python 02_skimo/train.py --overfit-one-batch --epochs 1000
python 02_skimo/train.py --epochs 20
```

One-batch mode performs only one optimizer update per epoch. Training previews
contain actual FINAL frames on top and decoded recursively PREDICTED final states
below, paired by column. They differ from image autoencoder reconstructions. Normal
training uses held-out trajectories for previews. Printed losses are training losses.
Each invocation starts fresh; checkpoint resumption is not implemented.

## Scope and later extension

This scaffold uses image observations, small MLP skills, two-block rollouts, and
mean-reduced objectives. Its prior is conditioned on a detached image embedding.
It does not implement the paper's downstream reward model, Q functions, task policy,
replay buffer, or CEM-based online control. Those are a subsequent milestone once
pretraining works. Offline endpoint prediction uses skills inferred from recorded
future trajectories; it does NOT demonstrate autonomous goal-reaching.

Before extending to control, verify action reconstruction, image reconstruction,
one-block prediction, then recursive two-block prediction independently. Later we
can add skill-space planning and compare predicted outcomes with actual dot rollouts.

## Adjusting dot size

Dots now default to Gaussian sigma 0.08, increased from 0.045. At 28x28 this
changes the full width at half maximum from about 2.9 to 5.1 pixels, making the
foreground easier to represent. Motion commands and trajectory positions stay the
same. Dots near borders may be partially clipped by the image boundary.

Use the same configurable size for training and validation:

```bash
python 02_skimo/train.py --preview-data --dot-sigma 0.08
python 02_skimo/train.py --epochs 100 --dot-sigma 0.08
```

The previous width is available with `--dot-sigma 0.045`. Each training invocation
starts fresh. Changing dot size changes the image distribution, so evaluate a new
run with its matching size. Foreground loss weighting can be tuned separately;
a larger dot does not by itself guarantee successful dynamics learning.

## Shared skill-network architecture

SkillEncoder, SkillPolicy, SkillDynamics, and SkillPrior use `make_mlp`:
two hidden layers of width 128 with ReLU, followed by a linear output. Gaussian
networks output `2 * skill_dim` values split into mean and log variance; log
variance is clamped to [-10,5]. Policy applies tanh to its final action output.
Image convolutional networks retain their existing projection layers.
Previous linear-network checkpoints are incompatible with this architecture;
start a fresh training run.
